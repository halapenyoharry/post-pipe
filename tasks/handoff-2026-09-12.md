## What was built

### The data layer

**`feed.json` is now a graph, not a list.** It carries an `edges[]` array beside
`items[]`, in the `GraphLink` shape the Exoskeleton graph panels already share
(`source, target, directed, role, layer, attrs`). Four relation kinds on three
layers:

| layer | count | relation |
|---|---|---|
| `authored` | 17 | `connected_to`, directed — A claims B, B need not agree |
| `tag` | 110 | `tagged`, undirected membership |
| `topology` | 30 | `exhibits`, a separate vocabulary from tags on purpose |
| `sequence` | 0 | `next`, directed, ordered by `series_part` — for a serialized novel |

Before this, the corpus had **zero** edges on disk. Seventeen hand-authored
`connected_to` relations travelled the entire pipeline intact and were discarded
at the last step, while 62 subject keywords were reified into graph nodes.

**Why it matters immediately:** `items` is already in the Exoskeleton
`detectGraph`'s `NODE_KEYS`, so adding the edges array is what makes the corpus
render in `json-graph`, `json-cytoscape`, `json-graph3d` and `topoviewer` with
no port and no post-pipe-specific transform. Verified live: 112 nodes /
128 links at the time.

**Label ladder.** Every item carries `labels.{short, medium, full}` — two words,
four words, the title. Computed at build time in `src/corpus/titleNucleus.js`,
deterministic, no key required. An authored `short_title` always wins, with one
word of slack against the budget. Contiguous phrases, not top-n scattered words:
picking the best words independently produced pairs like "Isn't Complexity".

**Prominence.** Sources declare `prominence="primary|secondary"` in OPML; local
defaults to primary, network to secondary. Card colour follows from prominence
*and* status, so your published work, your drafts, and subscribed items are three
distinct cards. Previously colour came from status alone, which meant your eight
drafts rendered identically to ProPublica articles.

### Persistence — `src/lib/viewState.js`

One store, three backends: `localStorage` for the static page,
`props.api.updateParameters` for a Dockview panel, memory for tests. The port to
a panel changes the adapter, not the store.

- Keyed by **item permalink**, so a feed adding sixty items overnight leaves the
  arrangement alone. Positions are additionally namespaced per layout
  (`ring::<id>`), so an arrangement made in one layout survives a trip through
  the others. Sizes are keyed by item alone — how big you made a card does not
  depend on where it sits.
- **Bounded.** `prune()` keeps everything present, then departed items to a cap,
  most-recently-touched first.
- **A drag is one undo,** not one per frame. Transient updates accumulate against
  a gesture baseline; `commit()` folds the gesture into one history entry.
- **Scrolling never enters history.**
- Three write modes: normal (undoable), transient (mid-gesture), silent (the
  layout's own output, invisible to history, applied to an open gesture's
  baseline too so undo does not sweep it up).
- **Layout versioning.** `LAYOUT_VERSION` in `generate-index.js` distinguishes
  positions the *layout* generated from ones the *reader* placed. Bumping it
  discards the former and keeps the latter. **Bump it whenever anything changes
  what a node physically occupies.**

### Layouts — `src/components/GraphViewer/layouts.js`

Pure functions, no D3, no DOM. 25 tests.

- **cluster** — the force simulation. Asking for it re-runs it when there is no
  arrangement to return to.
- **ring** — up to four concentric ellipses, articles on the rims sorted by
  source (each feed becomes a contiguous arc), tags on a phyllotaxis spiral
  inside. Spaced by arc length, sized from the measured *chord*. Zero overlapping
  pairs at 10/60/102/200 pieces.
- **timeline** — compressed time axis (fourth root on the gaps), greedy lane
  packing, undated items in their own block left of the axis.
- `layoutIsDegenerate()` — the guard described under Known Traps.

### The time rail

A ruler pinned to the **window**, not an object in the canvas: the axis layer is
a sibling of the zoom container, so the corpus pans and zooms underneath while
the rail stays put. Docked left by default (`graph.timeAxis.dock`), earliest at
top, ticks on round dates that thin themselves when they would collide.

Connectors have one end in screen space and one in graph space, re-projected
through the zoom transform on every pan, zoom, tick, node drag and resize.

**This is the thing to preserve conceptually:** time is drawn as a *relation*
rather than spent as a *coordinate*, so it composes with any layout. You can
read topic clustering and chronology at once. Harold's idea, not mine.

### Other

- **Node resize** — grip on a pinned card, bounded, persisted, one undo.
- **Touch** — `touch-action` on the canvas and the card body; a drag filter so a
  touch starting in scrollable text scrolls instead of dragging; larger hit
  areas under a coarse pointer.
- **TTS** — engines split into `available` (ships and works) vs `exposed` (offered
  in the picker). Browser/Web Speech is the default: free, offline, no key.
  Gemini is available and unexposed.
- **Build scripts** — `npm run build` (standalone, React bundled),
  `npm run build:lib` (React external, `dist-lib/`, 283 kB → 93 kB), `npm test`.
- **Feeds** — ScienceDaily and ProPublica subscribed; the RSS/Atom/JSON adapters
  ran against real feeds for the first time and work.

## Settings surface

`settings.json` gained a `graph` section holding every visual constant that used
to be a literal in a component: card sizes and bounds, corner radius, glow
padding, label font range, compact threshold, image-mark size; tag font,
padding, wrap width, lines, radius, opacity; time-rail dock, inset, end padding,
connector and spine weight and opacity, tick font; simulation link distance,
charge, collide padding, velocity and alpha decay.

Components keep the previous values as defaults and merge settings over them, so
a missing or partial section renders exactly as before. Nothing new is exposed
in the interface. Being reachable without editing a component was the point.

## Known traps — read before debugging anything visual

These each cost real time this session.

1. **A hidden tab gets no animation frames.** d3-timer runs on
   `requestAnimationFrame`, so a page never looked at never lays out — nodes stay
   in d3's initial spiral, ~260px across whatever the corpus size. Twice this
   looked like a layout bug and was not. There is now a `visibilitychange`
   handler that starts the simulation when the page is first actually seen.

2. **Never persist an unsettled layout.** If that spiral reaches storage, every
   later load restores it and skips both the settle and the fit, because it looks
   like an arrangement the reader made. The graph is then permanently a pile and
   reloading never fixes it. It happened: 178 nodes at a 256×257 extent with
   9,121 overlapping pairs. `layoutIsDegenerate()` guards both directions —
   a stored heap is ignored, a live heap is never written.

3. **`getBBox` on SVG text returns the em box, not the ink.** It is built from
   font ascender/descender metrics, so identical padding reads as unequal.
   Canvas `measureText().actualBoundingBox*` gives true ink. This is why tag
   margins measured 11px on all sides and still looked wrong vertically.

4. **Text metrics change when the webfont loads.** Anything measured at first
   paint needs a second pass after `document.fonts.ready`.

5. **d3-drag ignores synthetic pointer events.** A scripted drag silently does
   nothing and looks like a broken feature. Use real input (the browser tool's
   `left_click_drag`).

6. **Do not write state on every frame of a drag.** It re-runs the effect, which
   tears down the element under the pointer. Apply the offset to the DOM during
   the gesture, commit once on release.

7. **A zero-size container gives a zero scale.** `fitToViewport` divided by
   `clientWidth`, which is 0 before layout — collapsing the whole graph to a
   point. Page renders, nodes all correct, nothing visible.

8. **The generated page was being served from cache.** Fixed (no-store meta plus
   a generator timestamp, and the preview server sends no-cache), but several
   "it still looks wrong" rounds were a stale `index.html` rather than a bug.
   If a change appears not to have landed, check the generator timestamp in view-source first.

9. **Collision radius must match the real footprint.** It was `size/2` — 30, for
   a 180×140 card. And ring spacing must be budgeted against the ellipse
   flattening, not the radius: rings differing by R are only `R × flatten` apart
   at the top, which is where they are closest.

## Next steps, in dependency order

### Tier 1 — finish what is started

1. **Make the viewer consume `feed.edges`.** *Still outstanding and it is the
   biggest one.* `feedToGraph()` in `GraphViewer.jsx` still derives links from
   `item.tags` and reifies each tag into a node. It never looks at `feed.edges`.
   So the 17 authored edges are in the data, render in Exoskeleton, and **still
   do not appear in post-pipe's own graph.** Roughly 60 lines, deletes the
   reification, and is work the panel port needs anyway.

2. **Ship the missing `kokoro-worker.js`.** `tts.js` does
   `new Worker('./kokoro-worker.js')`; the file is not in `_site/` and
   `generate-index.js` never copies it. The worker 404s and the promise never
   settles, so Kokoro hangs on "loading" rather than erroring. Either copy it at
   build time or wire `graph`-style settings for `mode: 'server'` + `host` against
   an OpenAI-compatible `/v1/audio/speech`.

3. **TTS inside the node.** TTS mounts only into the ReaderPanel
   (`generate-index.js`, via a separate root and a `targetRef`). You read in the
   node, so you should be able to listen in the node.

4. **Feed autodiscovery for the `+` button.** It accepts an RSS/Atom/JSON Feed
   *URL* only. Nobody knows their favourite site's feed URL. Fetch the page, read
   `<link rel="alternate">`. ~20 lines, largest usability win available.

### Tier 2 — the things the corpus is asking for

5. **Orphans: 66 of 102 items have no edge at all.** Sixty are ScienceDaily,
   whose RSS carries no `<category>`. Two-thirds of the graph is disconnected
   dust. This is the Rosetta-stone problem arriving concretely — sources sharing
   no vocabulary produce no edges between them. It is the argument for
   edges-first made by the data rather than by theory.

6. **Read / unread / new.** Designed, not built. No accounts, no server: per-viewer
   state keyed by item id in the same persistence layer. For multi-device, sync
   the blob through Syncthing — Harold's own infrastructure, nobody's login.

7. **Per-feed display parameters.** `prominence` is in; the general form is not.
   Node scale, item cap, default-hidden, density weight, per feed.

8. **Accessibility, which is the same artifact as the density fix.** A force
   graph is unreachable by keyboard and opaque to a screen reader. A linear,
   structured, keyboard-navigable view of the same corpus answers both that and
   "I can see the shape but can't read it at 102 nodes". Build it once, solve
   both. Harold founded Apple's accessibility support team; this should not be
   the weak spot.

### Tier 3 — the port to Exoskeleton

The panel is to be called **`graph-reader`** — not `node-reader`, deliberately:
naming it after the node would bake node-privilege into the identity, and if
edges are first-class they get equal treatment eventually. See
`~/.claude/projects/-Users-harold-Projects-post-pipe/memory/project_graph_reader_panel.md`.

9. **Externalise React.** `src/index.jsx` currently ends with
   `export { React, ReactDOM }` — the library ships its own React. Two copies in
   one host means hooks throw. `build:lib` already proves the components survive
   it (283 kB → 93 kB).
10. **Convert `.jsx` → `.tsx`.** `manifest.ts` imports the component with a typed
    params interface, and the fork builds `tsc && vite build`. Biggest mechanical
    chore in the list.
11. **Write `manifest.ts` + the panel `README.md`** — id, title, accent, glyph,
    `defaultLayout`, `capabilities`, `companions`, `npmDependencies`.
12. **Return a fragment, no root wrapper** — the host supplies `PanelRoot`.
13. **Swap the persistence backend** to `hostParamsBackend`, which already exists
    and is tested.

### Tier 4 — the long arc

14. **Edges as first-class as nodes.** Harold's own framing: if an edge is a real
    citizen it should be readable the way a node is readable — which means an edge
    needs a *body*, not just properties, which means an edge can be a bundle

    Parked deliberately; the tag-click-highlights behaviour is already a vector
